## v0.16.4 — 修「草图」勾选框点不动（mxGraph 样式值 number 陷阱）

**现象**：绘图面板「样式」Tab 的「草图」勾选框点了一瞬间就弹回未勾选，视觉上「无法勾选」。

**根因**（已在真实 `src/mxClient.min.js` 上实证）：`mxStylesheet.getCellStyle()` 解析样式串时对纯数值值做 `mxUtils.isNumeric(f) ? c[k]=parseFloat(f) : c[k]=f`，
所以 `sketch=1` 读回来是 **number 1**。而 `applyStyleToPage()` 写完样式会同步调 `drawPanel.refresh()`，
里面 `this.sketchCheck.checked = getPageStyle("sketch") === "1"` → `1 === "1"` 为 false → 刚勾上就被抹掉。
同一类 bug 还波及：阴影、圆角、虚线判定（永远显示实线）、水平书写方向、HTML 标签、锁定（FormatPanel 与右键菜单都失效）、翻转 flipH/flipV。

**修法**：
- 新增 `src/styleValue.ts`：`isStyleOn(v)` = `v === true || String(v) === "1"`、`styleIs(v, expected)`。写入侧仍写字符串 `"1"`（draw.io 互通）。
- 全仓 15 处 `=== "1"` / `=== "0"` 比对改走这两个函数（FormatPanel、DrawPanel、DrawioView、SketchRenderer）。
- `getPageStyle()` 返回类型改成 `string | number | null` 并在注释里标注陷阱；DrawPanel 里 `adaptiveColors` 加 `typeof === "string"` 守卫。
- 页内无图形时整图级样式无处可写：`applyStyleToPage()` 早退分支补 Notice（新 i18n key `diagram.styleNeedsShapes`），不再让控件静静弹回。
- 圆角按钮去掉点击里手动的 `classList.toggle("active")`，状态只由 `refresh()` 从模型回填，避免无图形时留下「已开启」假状态。

**验证**：tsc 通过；esbuild `--production` 通过；抽出 mxClient 里 `getCellStyle` 源码 + 桩离线跑，证明 `sketch/rounded/shadow/dashed/glass/html` 都是 number；产物内中英文案已打入；源码已无比对残留。

**顺带**：并行对同一文件发多个 Edit 会互相覆盖（当时 `toggleFlip` 那处改动被冲掉，靠收尾自查脚本才发现）→ 同一文件的编辑一律串行。

**版本**：manifest/package/versions 三处同步升到 0.16.4（0.16.3 是上一版草图渲染）。

## v0.16.4 续 — 草图「手绘感」不足，先出 HTML 原型（未改源码）

用户看过 v0.16.4 的草图效果后反馈：勾上后虽然不再弹回，但**视觉不像参考图（draw.io 的手绘风）**。

**量化了参考图**（`clipboard-2026-09-14T02-41-04-212Z-1abb8003.png`，475×255，纯 Node 手写 PNG 解码 + 阈值化 + 游程分析，脚本在 `%TEMP%/mxprobe/`）：

| 特征 | 实测值 |
|------|--------|
| 笔画数 | **4 笔**，各自独立、不闭合 |
| 理想矩形 | x 142~292（150px）× y 75~150（75px） |
| 上横弓形 | 相对首尾连线鼓出 **7.1px**（占边长 5%） |
| 下横弓形 | 鼓出 **12.5px**（占 8.7%） |
| 两竖弓形 | 鼓出 **5.6 / 7.4px**（占 8~10%） |
| 端部越界 | 5 ~ **16px**（右竖底端最长） |
| 笔宽 | 1.5 ~ 2.2px，沿笔略有起伏 |

**结论**：参考图的手绘感 ≈ `弓形(占边长 5~10%) + 端部越界(5~16px) + 每边独立一笔 + 笔宽起伏`，

**已产出原型**：`prototypes/sketch-renderer.html`（可实时调 6 组参数 + 切换 3 种渲染方案 A/B/C + 拖拽缩放），等用户确认参数后再改 `src/SketchRenderer.ts`。

## v0.17.0 — 草图改为「边整体歪斜」（用户砍需求，方案 C 极简版）

**用户反馈拍板**：看过原型后不要 A/B/C 那套弓形/拆笔/端部越界，原话「就是图形边框有点歪歪扭扭的样子即可」，
参考图二（`clipboard-2026-09-14T02-55-16-670Z-15f7ecc1.png`）是**边保持直线、整体被斜推**（平行四边形感），不是手绘曲线。
追问确认三项：歪斜幅度=**轻微**、范围=**图形+连线**、填充处理=**描边歪、填充平整**。

**关键认知：为什么旧实现做不到「歪」**
旧版对每个坐标**独立**随机 ±2.2px → 得到的是「毛边」（edge 仍笔直，只是锯齿轮廓）。
参考图要的是**整条边一起倾斜**，即相邻顶点的位移必须**相关**。随机独立位移做不到这一点。

**新算法（三层叠加，`vertexDelta()`）**：
1. **剪切场 SHEAR_AMP=1.6** —— `Math.sin(相位 + (vi / 波长) * 2π)`，沿顶点序号铺低频正弦。
   相邻顶点相位接近 ⇒ 一条边两端几乎同步移动 ⇒ 边整体倾斜；跨半波长后反向 ⇒ 上下/左右边相对收拢。
   这是「歪」的主力。
2. **低频随机 LEAN_AMP=0.8** —— 同一分组（`⌊vi/2⌋`）共享，打散剪切场的规律性，避免所有图形歪成同一形状。
3. **高频手抖 JITTER_AMP=0.7** —— 每顶点独立，让边不那么光滑。
- `SHEAR_WAVELENGTH=2.0`；`SHEAR_Y_WAVELENGTH_RATIO=1.6` —— x/y 用**不同波长**，否则图形退化成统一旋转，反而不像手绘。

**实测效果（150×75 矩形，20 组种子）**：平均倾角偏移 1.03°、最大 3.32°；40×40 方块 2.41°/6.23°；300×200 大矩形 0.42°/1.27°。
位移是**固定像素**（最大 ~2.9px），所以小图形相对更明显、大图形更稳 —— 与手绘一致。
形态分布：平行四边形（整体斜推）12 / 混合 10 / 梯形（收拢）2 —— 与参考图二的平行四边形观感一致，**不需要再改成梯形**。

**「描边歪、填充平整」的实现方式（重要）**：mxGraph 的矩形/椭圆等 shape **只有一个几何节点**，填充和描边共用它，
没法只改描边。所以对带 fill/stroke 的几何统一只做**坐标平移、不改尺寸**（`width/height/rx/ry/r` 一律不位移），
保证填充块与描边轮廓始终对齐、不露白边。要真正让填充也歪只能改填充路径，成本不值得。

**圆弧处理（踩坑）**：`A rx ry x-axis-rotation large-arc-flag sweep-flag x y` 是 7 个一组。
最初误按 `inGroup===1`（ry）跳过，导致 `A 30 20 0 1 0 60 0` 里把 `20`（ry）当 sweep 标志位丢掉、几何错乱。
正确判定是 **`g<=4` 全部原样保留**（rx/ry/rotation/两个 flag），只有 `g===5|6`（终点 x/y）参与位移，
且整条弧共享一个锚点 `"arc" + ⌊argCount/7⌋`，让弧整体倾斜而不散开。

**幂等性验证要点**：mxGraph 每次重绘都用**模型里的原始几何**重新生成 `d`（不是拿上次结果再抖），
所以只要种子只依赖原始几何，连续三次重绘结果完全一致 —— 不会「越抖越歪」。这条已写成断言。

**验证法**（脚本在 `%TEMP%/mxprobe/`）：
- `sketch-verify.js` —— 用 **`typescript.transpileModule`** 把 TS 源转成 JS 再 `vm.runInContext`（比正则剥类型注解稳，
  最初用正则清箭头函数返回类型 `: () => number` 没清干净，直接 SyntaxError）。29 项断言全过。
- `angle-measure.js` —— 用**倾角偏移（度）**度量，别用斜率：垂直边 Δx→0 时斜率会爆到 845/949，那是度量方式的问题不是 bug。
- `shape-survey.js` —— 抽样看形态分布（平行四边形 vs 梯形占比）。
- `verify-build.js` —— 版本三处一致 + 源码旧逻辑已移除 + 中文文案反转义后在产物中全命中（265 条）。

**原型**：`prototypes/sketch-wobble-preview.html` —— 与 `SketchRenderer.ts` 同算法的可交互预览（8 种图形、4 档参数滑杆、换种子、原始轮廓对照）。

**版本**：按视觉特性升级，Minor → 0.17.0（manifest/package/versions 三处同步）。
