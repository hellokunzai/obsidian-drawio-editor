## 框选交互对齐 draw.io（v0.8.0）

新增 `DrawioView.setupRubberbandSelection()`，替换原来的裸 `new MxRubberband(graph)`。

关键结论（mxClient 内置实现，长期有效）：

- `mxRubberband.mouseUp` → `execute()` 里 `this.x/y/width/height` 是 **页面坐标**（`mxMouseEvent.getX()` 是 clientX 量级），
  但 `graph.selectRegion` 期望的是 **图坐标**（`getCells` 直接拿它和 `state.x/y` 比）。两者只在
  画布左上角 ≈ 页面原点时才碰巧相等 → 这是原实现框选区域偏位的根因，缩放/平移后更明显。
- 正解：`graphSpace = page / view.scale - view.translate`。
  `first` 由 `mxMouseEvent` 生成、`currentX/Y` 由 document 上的原生鼠标事件生成，两者都是页面坐标，可直接相减。
- 拖拽框 div 的定位（`div.style.left = this.x`）用的是页面坐标是对的，**不要动 repaint 的定位部分**。
- `mxRubberband` **没有** `region` 字段，需自己挂；覆写 `graph.isCellSelectable` 时用 `rubberband.region`
  做「严格包含判定」（`mxUtils.contains`，对应 draw.io `Kc` 的 isVertex+contains），
  并排除 `cell === rubberband.div`（`getCells` 会遍历容器里的 div），避免框选过程中框到自己。
- 覆写 `isCellSelectable` 会波及 `setCells` / `addCells` / `getFirstSelectableCell`，
  但点选时 `region` 为 null → 全放行，互不干扰。
- 顺带修真 bug：`isCellVisible(mxCell)` 让 `getCells` 永远跳过 `mxCell`，而 `selectRegion` 又靠
  `isCellSelectable(mxCell)` 兜底，导致**每次框选都会把根单元格选中** → 覆写里对 `mxCell` 直接放行解决。
- `rubberband.reset()` 走 fadeOut 用 200ms 计时器、**不登记进 mxGraph 定时器列表**：图销毁后回调仍会跑
  `removeChild`。若 `graph.container` 已被移出 DOM 会抛 NotFoundError。本轮靠 Tab 切换路径未复现，
  但图真实 destroy 时要留意（`.remove()` / `isConnected` 保护）。
- 顺手修：`updateGridBackground()` 增加 `!container.clientWidth` 保护，避免面板折叠（宽度 0）时
  写出 NaN 导致整条 background 声明失效、残留旧网格。

- 同步升级三处版本号 → `0.8.0`（新功能 Minor）
- 构建验证通过：tsc + esbuild --production 均 exit 0

未做 git 提交 / 未发布。

## 框选交互修正（v0.8.1）— 上一版 v0.8.0 分析有误，本版才是真修

**更正 v0.8.0 日志里的错误结论**：`mxRubberband` 的 `this.x/y/width/height` **不是** clientX 页面坐标，
而是**容器本地像素坐标**——repaint 里 `div.style.left = this.x + "px"`（div 是 container 的子节点），
即已扣除容器滚动与 `panDx`，但**还没除 scale**。

**v0.8.0 为什么"没修复"（两个真 bug）**：
1. `execute` 把 `this.x`（容器像素）原样丢给 `selectRegion`，而 `selectRegion→getCells` 要的是
   **图坐标** → 缩放/平移后选中范围整体错位（这是用户说"没修复"的根因）。
2. `repaint` 里又多减了一次 `origin.x`（容器偏移），实时高亮框也偏了两倍偏移。
   另外 `isCellSelectable` 覆写引用了从未定义过的 `rubberband.region`，恒为真 = no-op。

**真解（v0.8.1，与 HTML 原型算法一致）**：
- `execute` / `repaint` 里统一反投影：`graphX = px / view.scale - view.translate.x`
  （`this.x` 已是容器像素，不要再减 origin）。
- 严格包含交给 `getCells` 内部完成（`u.x>=a && u.x+u.width<=n` 的严苛区间，顶点走此分支）。
- 删除失效的 `isCellSelectable` 覆写；`mxRubberband-preview` 类按 `getCells` 命中数切换（>0 加粗）。
- 淡出阈值（RUBBERBAND_FADE_EDGE/RATIO）保留。

**流程改进**：本次先写 `prototypes/drawio-rubberband.html` 让用户确认交互，再移植进插件，
避免再次返工（用户明确要求"先原型后开发"）。

- 验证：tsc + esbuild --production 均 exit 0；bundle 确认 `o=(p,u)=>{let c=e.getView(),g=c.scale||1,C=c.translate||{x:0,y:0};return{x:p/g-C.x,y:u/g-C.y}}` 已进包，execute 走图坐标矩形。
- 版本号三处 → `0.8.1`，未提交未发布。

## 框选矩形没有边框/背景色（v0.8.2）— CSS 失效

用户实测 v0.8.1 框选**算法对了但矩形无边框无填充**。

**根因（styles.css 的 `.mxRubberband` 规则）**：
1. 用了 `color-mix(in srgb, var(--interactive-accent) 12%, transparent)` + `border: 1px solid var(--interactive-accent)`，
   一旦 `.drawio-graph-container` 作用域取不到 `--interactive-accent`，整条 `border`/`background` 声明失效；
   即便有变量，老版本 Electron 不支持 `color-mix` 时 `background` 也会失效。
2. **缺少 `position: absolute`**——原型里 `.rubberband` 有，但插件 CSS 覆盖 mxClient 默认类后没补，
   div 不是绝对定位，宽高被内联设置却叠不到画布上。

**修法**（对齐已确认的原型配色，去掉对 CSS 变量/color-mix 的依赖）：
- `border: 1px solid #167dff !important` + `background-color: rgba(22,125,255,0.12) !important`
- 补 `position: absolute !important` 与 `pointer-events: none !important`（避免遮住鼠标事件）
- `.mxRubberband-preview`（框内命中）`border-width:2px` + `background-color: rgba(22,125,255,0.24)`
- `repaint` 覆写只切 preview 类、不碰内联边框/背景，无冲突。

**结论（长期有效）**：本插件 CSS 给 mxGraph 元素上色时**不要依赖 `var(--interactive-accent)` 与 `color-mix`**，
直接用具体 hex / rgba，且凡是要覆盖 mxClient 默认类（如 `.mxRubberband`）必须补 `position:absolute`。

- 验证：tsc + esbuild --production 均 exit 0；styles.css 六条关键规则已确认存在。
- 版本号三处 → `0.8.2`，未提交未发布。

## 框选"靠近形状不生效"→ 改相交即选中（v0.8.3）

用户实测 v0.8.2：鼠标起框位置离形状近、框只压到形状一半（没把整块包进去）时，形状不被选中。
根因：上一版 `execute` 调用 `selectRegion` → `getCells`（**严格包含**：`u.x>=a && u.x+u.width<=n`），
只有形状**完全落在框内**才选中，与用户直觉（"框到了就算"）不符。

**修法**：`execute` / `repaint` 改用自实现的 `collectIntersecting(rect)`，遍历默认父节点子树，
对每个可见 cell 取 state（旋转用 `mxUtils.getBoundingBox` 修正包围盒），用 `mxUtils.intersects(rect, bb)` 判定
**相交即选中**，形状 + 连线都覆盖；`isCellSelectable` 过滤后 `setSelectionCells` 替换选择。
- 注意 `mxUtils` / `mxConstants` 在本项目是 `() => window.mxXxx` 工厂，必须调用 `mxUtils()` 才拿到对象，
  直接 `mxUtils.getValue` 会 tsc 报错且运行时 `undefined` 崩溃（esbuild 不报）。
- 该 mxClient 版本**无** `getCellsWithinArea`，但其 `getCells` 第 7 参数是相交矩形（仅顶点），故自实现覆盖连线。

- 验证：tsc exit 0；bundle 确认 `s.intersects(c,x)&&y.push(S)`（相交即推入）+ `setSelectionCells` 已进包。
- 版本号三处 → `0.8.3`，未提交未发布。

## 框选松手后图形不选中（v0.8.4）— isActive 阻断 execute 的致命 bug

用户实测 v0.8.3：蓝框（边框+背景色）拖拽正常显示，但**松手后图形完全不被选中**，连框选单个完整形状也不行。

**根因（精确定位，非猜测）**：逐行读 `mxRubberband.prototype.mouseUp` 源码：
```js
mxRubberband.prototype.mouseUp=function(a,b){
    var c=this.isActive();   // ① 调用 isActive()
    this.reset();            // ② reset() 清掉 div/first
    c&&(this.execute(b.getEvent()),b.consume())  // ③ 只有 isActive=true 才调 execute！
}
```
而我们的 `isActive` 覆写（从 v0.8.0 沿用）要求框**铺满画布大部分**才返回 true：
```js
return nearW && nearH;  // 小框/中框 → false → execute 永远不被调用！
```
**结果：任何正常大小的框选，`isActive` 返回 false → `mouseUp` 跳过 `execute` → 图形永远不会被选中。**
这是 v0.8.0~v0.8.3 三版"没修复"的统一根因——之前每版都在修坐标/CSS/包含判定，但全都被这个 `isActive` 拦截掉了。

**修法**：
- `isActive` 改为**始终返回 `true`**（用逗号表达式 `return this._shouldFade=..., !0`），同时把淡出判定结果存到 `this._shouldFade`
- 新增 `reset` 覆写：执行前临时将 `this.fadeOut` 设为 `_shouldFade` 的值，让原始 reset 走正确的淡出/移除分支，执行后恢复原值
- 这样淡出效果保留（仅大框时触发），但不影响 `execute` 的触发

- 验证：tsc + esbuild --production 均 exit 0；产物确认 `return this._shouldFade=v&&E,!0`（始终返回 true）+ reset 覆写读取 `_shouldFade`
- 版本号三处 → `0.8.4`，未提交未发布。诊断日志（[RB] 前缀）仍保留在代码中，确认修复后可删除。
